# Audit history implementation plan

**Goal:** Implement WHR-20 exactly against M3 amended by WHR-130, including its writer inventory.

**Architecture:** A shared strict audit contract validates canonical events. A transaction-bound persistence module records immutable snapshots; an independent projection validates current and legacy rows before filtering or returning them. Existing domain transactions retain their credit, receipt, permission and evidence semantics.

**Spec:** docs/engineering/contracts/m3.md and m3-audit-inventory.md.

## Constraints

- High risk, three review rounds maximum; independent code, security and integrity verdicts.
- Never rewrite existing audit rows. No audit edit, delete, export or retention flow.
- At most 100 typed changes and 20 related IDs. Closed action, actor, target and field matrices.
- No STATUS, coverage-map or lane edits. No provider, cloud or policy activation.
- AU-10 recovery hooks remain a future implementation dependency; existing P-26 meter decisions receive their specified projection.

## Tasks

1. Foundation builder owns `src/shared/contracts/audit.ts`, `src/server/modules/audit/**`, audit API routes, additive audit migration/schema and audit-specific tests. Define and communicate a transaction-bound writer interface before consumers integrate. Test exact field/action matrix and invalid values, safe legacy aliases/fallbacks, station ambiguity, immutable snapshots, auth and pagination, Lagos dates and append-only guards. Run focused unit/Postgres tests and commit explicit paths.
2. Sales builder owns sync, corrections, reviews and duplicates audit call sites plus their tests. Use the shared writer for AU-02/03: first receipt once, actual executor and original seller, effective V/G snapshots, candidates versus accepted pointers, decision/pair identity and P-25/P-26 projections. Test replay/rollback, mixed holds, pending/rejected contribution, duplicate pairs and meter-before-date preservation. Do not change credit rules.
3. Domain builder owns admin-access/auth, station/cards/customers writers, operator command and protected evidence resolver compatibility plus their tests. Implement AU-04/05/06/07/09 with exact boundaries, IDs instead of codes, durable verification transitions, fenced terminal export events and atomic operator events. Test failure/replay/rollback and canary omission. Retain protected provenance.
4. Integrate committed builder changes into the EM branch. Run independent test-engineer gap review against every audit verification requirement, adding real-Postgres regressions where needed. Verify canary phone, OTP, password, token, URL and digest values across storage, projections/search and captured logs; legacy sensitive rows remain untouched and inaccessible.
5. EM runs typecheck, lint, unit, build, real-Postgres integration and applicable e2e/time gates on final code. Dispatch all three read-only reviewers against the committed head. Fix within cap, commit validated evidence, push and merge into staging after required CI passes. Post named verification and READY to WHR-20.

## Review focus

- Historical station scope must be proved without mutable snapshot reconstruction.
- Search must match safe projections only, including sensitive historical free text.
- Database guards must preserve all old rows while rejecting ordinary updates/deletes.
- Operator rollback and export lease races must never emit false applied/terminal events.
- Writer normalization must preserve protected domain-audit evidence and effective contribution semantics.

## Method and evidence

Each product `Design System/components/<Name>/preview.html` fragment was rendered in Chromium with its original `fonts.css`, `tokens.css` and `bundle.css`. Attention uses KPI’s shared preview. This was a transient read-only reference operation: a localhost server served the source folder; no product source is imported by committed tests or application runtime. The reference renderer added UTF-8 metadata and substituted the approved local brand mark for the source’s inaccessible `/_blob/…` image URL. Temporary references are `/tmp/wo-app-1-reference/<Name>.reference.png` and are not a repository dependency.

Every source reference and built component capture was opened and visually inspected for layout, hierarchy, copy, status colours, typography, spacing and states. Built captures are in [tests/design-parity/design-system/screenshots](../../tests/design-parity/design-system/screenshots). These are inspection evidence, not automatically approved pixel baselines. Device scale factor is 2. Component preview nodes are 390px wide (phone) or 1440px (admin) using viewports 422px/1472px to account for the gallery’s outer 16px gutters. The 16 component captures retain the preview’s own inner spacing. Shell captures separately exercise actual viewport widths 360px, 1440px and 800px. Next’s development badge is hidden only for captures.

# P-26 adversarial PostgreSQL verification

Part of WHR-126. `meter-adversarial.test.ts` and `meter-health.test.ts` exercise the actual meter decision and health services against migrated PostgreSQL schemas. `meter.test.ts` supplies MR-T1-01–13; `meter-operator.test.ts` supplies operator lifecycle verification. All measured profiles here are fictional test fixtures.

`meterDenied` snapshots purchases, revisions, validation, corrections, holds, blocks, decision receipts, both evaluation tables, audit and giveaway snapshots before and after rejection. `meterSucceeded` checks immutable original facts, one meter evaluation and decision, historical replay and database append-only protection. Race tests additionally count meter applications and accepted revisions. The dedicated frozen-giveaway test compares snapshot, source and row tables byte-for-byte.

## Human and transport boundaries

P-26 keeps human transcription and adds no OCR or structured machine-readable visual-inspection verdict. Blurred, hidden, totalizer or contradictory display content must be rejected by the authorized human before submission. The approved proposal explicitly requires a meter pilot for that assurance. Tests do not relabel the harness's blank decodable JPEG as a readable meter or claim machine detection of those conditions; WHR-131 records the clarification. Numeric contradictions and unavailable/invalid bytes remain automated denials.

The implemented sync service has no recovered-original transport endpoint. MR-T1-14 tests the server invariant using preserved original context, a new online sign-in, a newly issued lookup receipt and same-operation replay, and denies recovery credentials any meter-decision authority. P-19 stored recovery attribution and maker exclusions are tested directly. These results do not claim an end-to-end recovered-original transport test for a future endpoint.
